# Разработка, Git и GitHub

Репозиторий уже инициализирован локально. Проверка: `git status`, `git log --oneline`, `git tag`.
Просмотр базового файла: `git show v1.0:strategies/orb-fade/v1.0.pine`.

## Новая версия

1. `git switch -c research/orb-fade-v1.1`
2. `cp strategies/orb-fade/v1.0.pine strategies/orb-fade/v1.1.pine`
3. Изменять только новый файл, обновить название стратегии и добавить отдельный config.
4. Скопировать backtests/templates/result.md в новый отчёт с уникальным run-id, записать commit исходника и все настройки.
5. Скомпилировать и прогнать вручную; сохранить реальные экспорты, сравнить с baseline и независимым периодом.
6. Обновить CHANGELOG, проверить `git diff`, выполнить `git add <конкретные-файлы>` и `git commit -m "Add ORB Fade v1.1 experiment"`.

Не передвигать tag v1.0. Исправления базового алгоритма также требуют новой версии.

## Публикация на GitHub

Remote: git@github.com:VadimV3/trading-NY-Session.git (репозиторий указан пользователем). Видимость существующего репозитория не менялась. Исходный архив публикуется в main с tag v1.0.
После выбора владельца создать пустой репозиторий без README, лицензии и .gitignore. Затем выполнить, подставив фактический URL:

```sh
git remote add origin <фактический-URL-репозитория>
git remote -v
git push -u origin main
git push origin v1.0
```

Не вставлять токены в URL или файлы. Перед публичной публикацией проверить персональные данные на скриншоте и права на исходник/данные. Лицензия пока не выбрана.

## Будущий CI

Подключить отдельным изменением после выбора GitHub: проверка checksums.sha256, JSON/CSV, обязательных полей отчётов и неизменности v1.0 относительно tag. Сверка метрик потребует настоящего CSV и документированной методики. Pine-компиляцию и платформенный бэктест нельзя объявлять прошедшими по одной статической проверке. Подтверждённый compiler/API пока не подключён. Секреты хранить в GitHub Secrets.
